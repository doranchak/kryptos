Polyalphabetic Alphabet-Keying Coverage

Which of the Cipher Generator's polyalphabetic cipher families support a keyed plaintext alphabet, a keyed ciphertext alphabet, or both — and which combinations are still gaps.

This covers every cipher built around a per-position, key-driven substitution formula — some plaintext alphabet + some ciphertext alphabet + a key stream — as distinct from transposition, fractionation (Bifid/Trifid/ADFGX/ADFGVX), Playfair, Hill, or Enigma, where "keyed plaintext/ciphertext alphabet" isn't a meaningful axis in the same way.

There are six such base mechanisms in the generator, distinguished by how the key stream is produced. Each can in principle be run against four alphabet configurations: both straight, keyed plaintext only, keyed ciphertext only, or keyed on both sides (with one shared keyword, or two independent keywords).

Already fully covered

The cycling-indicator mechanism (Vigenère / Quagmire I–IV) and the unrelated running-key mechanism (Running Key / Running Key I–IV) are both complete: every one of the four alphabet combinations already exists for each.

Gaps — straight/straight only, no keyed-alphabet siblings

  1. Running Key ACA. The variant just added has no keyed-alphabet siblings yet. A "Running Key ACA I/II/III/IV" would apply Quagmire's four alphabet combinations but source the key as the adjacent, same-source text (like the base ACA variant does) rather than a cycling indicator or an unrelated running key. Same shape as running_key1-4, just swapping the key-sourcing.
  2. Autokey. A strong candidate: the extending key (primer, then plaintext) is exactly the kind of key stream Quagmire / Running Key I–IV already generalize over. "Autokey I/II/III/IV" is well-defined and currently missing entirely.
  3. Beaufort. Self-reciprocal (C = K − P), currently straight/straight only. Keying either or both alphabets is mathematically well-defined — mirrors the Quagmire derivation with subtraction instead of addition — and currently has no representation.
  4. Porta. Its reciprocal 13-group construction inherently ties the plaintext and ciphertext alphabets together (built from one alphabet split into pairs), so the natural single extension is a Quagmire-III-style "one keyword keys both sides" Porta. Asymmetric keyed-PT-only or keyed-CT-only variants don't fit Porta's construction as cleanly and would be more of a stretch.

Caveat on authenticity: unlike Running Key I–IV (directly modeled on the well-established Quagmire structure) and Running Key ACA (a real, named ACA cipher, sourced from cryptogram.org's reference PDF), there's no confirmation that "Beaufort I–IV," "Autokey I–IV," or a keyed Porta are historically-attested named ciphers in the ACA canon. They're mathematically clean, well-defined extensions by analogy — not verified against an external reference the way everything else in this tool has been. Worth flagging if historical fidelity matters before building any of them.
